# 作文批改模式 落地計畫(2026-09-19 草案)

> 依據:09-19 一日實驗(115 會考寫作樣卷 25 篇,帳本見 `redpenaisever/docs/實驗成本記錄.md`「作文模式」各段;腳本與檢視頁在 `redpenaisever/local-only/essay/`)。
> 狀態:**未動工**。114 年樣卷驗證通過後才凍結 prompt、開始 P3。

## 0. 產品定位(已拍板)

- 價值主張=**逐句眉批**(原句→問題(掛向度+會考規準用語)→示範改寫→為什麼)+疑似錯別字+段落建議;**級分只是附帶的成績數字**,AI 給建議、老師拍板。
- 只收**系統製作稿紙**(格式比照會考:每頁 23 直行×22 格、行間窄欄、兩頁);第一版不支援自備稿紙。
- 筆畫級錯字(字「裡面」寫錯)**不處理**,產品頁註明;別字必須照抄保留。服務對象以國中為主。
- 作文功能**另外定價**(每篇 AI 成本約 NT$4~4.5:抄寫 2.2+眉批 1.3+級分/錯字 0.5~1)。
- 官方樣卷只當內部驗證資料,**不內建進產品**(著作權屬心測中心)。

## 1. 實驗已確立的技術決策

| 環節 | 決策 | 證據 |
|---|---|---|
| 抄寫單位 | 逐直行、每行一次呼叫;整篇一次抄否決 | 整篇:三輪回 31/16/10 行、字錯率 4~24%;逐行:1.2~2.1%、三輪幾乎逐字相同 |
| 抄寫設定 | 3.6-flash、temp 0、MINIMAL、HIGH(同線上級分抄寫員) | 732 行 0 失敗 |
| 裁切 | 每行只含**右側**窄欄(插入字慣例寫右側) | 含兩側 → 插入字被鄰行誤收(5-10 事故),修正後 15/29 行改善 |
| 低信心 | **數格子驗證器**(零 AI):每行墨格數≠抄本字數 → 旗標,交老師補 | 抓到全部漏字/多字/疊字行;旗標率 ~18%(每篇 5~6 行) |
| 級分 | 通用規準即可(±1 25/25);AI 生成的「題目專屬判準」會把切題寫窄、反而變差;向度分數有光環效應不可拿來合成 | 完全一致 A 13/25、B 11/25、C(錨點)17/25 |
| 錨點卷 | 不要求老師先批;改「AI 先全批→老師改過的卷自動成為錨點→其餘一鍵重判」(**未驗證**) | 流程與現場不合(user) |
| 眉批 | 3.6 預設 thinking、每篇 1 次;每則帶 dimension+rubricTerm(固定用語表)+四向度整篇診斷 | 對官方樣卷說明召回 75%;對 5/6 級分卷過度挑剔(多點 48 項)→ v3 要加程度詞校準 |
| 引用句 | code 驗證「逐字出自抄本」並定位回 頁/直行 | 115/119 可定位 |
| 錯別字 | AI 列出 × 教育部辭典同音替換(純 code)交叉:一致=直接標;只有 AI=「疑似,附該格原圖,老師一鍵確認」;只有字典=不顯示 | 一致 14~16 個幾乎全真;只有字典 30 個多為誤報 |

## 2. 分期

### P0 前置(不寫產品 code)
1. ✅ **114 年樣卷驗證(09-19 完成、四條過關線全過)**:26 篇、看圖寫作題。抄寫 764 行 0 失敗、旗標率 20.3%、級分 ±1 26/26(通用規準完全一致 17/26;AI 題目專屬判準再次變差 10/26;錨點 20/26)、眉批 v3 召回 70%。115 的結論全部複現。
   - 新需求:**題本可能是看圖寫作** → P2 建卷時 AI 要把圖片轉成「客觀圖意描述」存進答案卷、老師可改(驗證時圖意是人工寫的)。
2. ✅ 眉批 **v3 已定版**(`local-only/essay/exp2v3-feedback.mjs`):整篇診斷加程度詞(偶有/明顯/嚴重)+列入門檻。115:召回 64%/精確 62%(v2=75%/57%);官方說明本身簡略,「多點」不等於錯。
3. 教育部辭典授權到「教育部公眾授權網」做第一手確認(目前依 g0v/moedict-data README:CC BY-ND 3.0 TW、不限格式轉換與後續應用)。
4. 找一批**真實學生稿紙掃描**(含注音、髒污、歪斜)補驗抄寫——樣卷是乾淨掃描、且沒有任何注音樣本。
5. 定價:作文每份扣幾點(成本 ≤ 售價 6 折原則)。

### P1 系統稿紙(client)
- `redpenai/src/lib/answerSheetGenerator.ts`(RPGEN3 排版器)新增「作文稿紙」版型:23×22 格、右側窄欄、定位錨點、座號 OMR(沿用 `answerSheetLayout.ts` 的 RPOMR1 幾何)。
- 稿紙幾何(頁數、行列數、格座標 mm、版本號)寫進 `answerKey`(沿用 `generated_sheet`,不加 DB 欄位);這份幾何是裁行、數格子、檢討單疊圖三處共用的 SSoT。
- 走既有「系統製作作答卷」路徑(`sheetSource='generated'`),批改端天然免 classify。

### P2 建卷=作文的「答案卷」(client) ✅ 已上線(09-19)
- 實驗4 定案:**批改時直接把老師上傳的題本圖送給 AI**(級分 7/7 完全一致且三輪全同、眉批與文字版持平 14/23 vs 14/23;AI 轉述圖意會失真(漏「籠門開著」)、AI 起草的「可接受的詮釋範圍」讓給分偏高搖擺)。user 定調:級分 ±1 即可、重點在眉批細節。
- 流程只有兩步:①基本資料(領域=國語才出現「作文模式」卡)→ ②上傳作文題目(刪封面/旋轉/排序=老師的檢查點、上限 2 頁)→ 老師按「儲存作文答案卷」(沿用儲存前確認框、作文專用文案)。**沒有 AI 起草、不花建卷次數、沒有要審核的 AI 草稿。**
- 答案卷內容:`answerKey.essay = { topicSource:'booklet_image', rubricPreset:'cap_6level' }`、整卷一題 `questionCategory:'essay'`、滿分 6(級分即分數);題本圖走既有的 question booklet 上傳;稿紙(RPESSAY2:B4 橫式、直書、右側直式座號欄=RPOMR1 順時針轉 90°)存檔時產生、寫進 `generated_sheet`(帶 `essay` 幾何)+兩頁 PDF,下載走答案卷卡片的「下載作答卷」圖示。
- 領域專屬模式對照表:`sheetSource.ts` 的 `SHEET_SOURCE_DOMAINS`。

### P3 批改管線(server,`staged-grading.js`)
- Phase A:依稿紙幾何切直行(sharp)→ 數格子(墨格數)→ 空白行略過 → 逐行抄寫(新 route `grading.essay_transcribe`,設定同 `LEVEL_TRANSCRIBE_GENERATION_CONFIG`)→ 字數不符的行標 `lowConfidence`。
- Phase B(**題目輸入=題本圖**,每次呼叫附上 template 的題本頁、最多 2 頁):①眉批+四向度診斷(`grading.essay_feedback`,3.6 預設 thinking)②建議級分(`grading.essay_level`,MINIMAL、通用規準)③錯別字交叉(教育部辭典預處理成「詞集合+同音表」JSON 隨 server 部署,純 code)④引用句子字串驗證+定位。
- 零 AI 閘門:空白卷、字數過少、與題幹高相似度(抄題幹)→ 直接給 0/1 級分候選並標記,不花眉批的錢。
- 結果存 `submissions.grading_result.details[0].essayResult`:`{columns[{page,col,text,lowConfidence}], feedback{sentence[],paragraph[],strengths[],diagnosis[]}, typos[{wrong,correct,loc,source:'both'|'ai_only',confirmed}], level{suggested,final}, promptVersion}`。
- 冷凍:登記 `JUDGE_PROMPT_VERSIONS`(`judge-verdict-cache.js`);同抄本+同版本不重判。回退開關 `ESSAY_MODE_ENABLED`。
- 重批規則:老師改過的抄本/眉批/級分不被自動覆蓋(沿用「不自動覆蓋老師花錢的批改」不變量);「一鍵重判其餘未確認卷」帶入已確認卷當錨點。

### P4 老師複核 UI(client)
- 新元件 `EssayReviewModal`(由 `SubmissionDetailModal` 在 `essay` 題型時開啟;z-index ≥ z-[120]、hooks 放 early return 前):
  - 左:原卷(低信心直行框色)/中:抄本(低信心行可點、帶該行原圖就地改字;疑似錯別字附該格小圖一鍵 確認/不是)/右:眉批卡(依向度分組,可刪改增)+建議級分(可改)。
  - 點眉批 ↔ 原卷與抄本同步高亮。
- 老師編輯欄位走 local 優先的 sync 規則;sync 加欄位時 SELECT 與 response map 兩處一起改。

### P5 學生檢討單(client,`reviewSheetPdf.ts` overlay 模式加 essay 分支)
- 原卷做底:錯別字紅圈+窄欄寫正字、有眉批的句子沿直行畫紅線+編號①②③;眉批全文放頁面下方或另起「批改建議」頁(編號・向度・問題・建議);首頁右上級分+總評。只印老師確認過的項目。

### P6 教師檢討模式(client,`ReviewModeOverlay` essay 版)
- **以向度+規準用語聚合**全班眉批(純 code 計數,切忌用級分分類):例「【遣詞造句・敘寫口語】12 人」。
- 每個共同問題:2~3 個同學原句(預設匿名)+示範改寫前後對照+一個寫得好的同學句子當正例;「挑範例句」用一次 AI。

### P7 計費
- `server/action-billing.js`/`exam-pricing.js`(兩端鏡像)加作文每份點數;重批照扣、老師手動修改不扣(沿用現行語意)。

## 3. 建議順序與 MVP 切法
1. P0-1(114 驗證)+P0-2(眉批 v3)→ 過關才往下。
2. **MVP=P1+P2+P3+P4(精簡版:抄本可改、眉批可刪、級分可改)+P7**。
3. 第二波=P5 檢討單、P6 檢討模式、「一鍵重判(錨點)」。

## 4. 未解風險
- 注音、真實掃描品質(歪斜/髒污/鉛筆淡墨)未驗;數格子的墨量門檻是在乾淨掃描上定的。
- 錯別字假指控:抄寫員抄錯會算到學生頭上 → 只有 AI 的一律要老師確認;回頭看圖二選一複核有知答偏誤(誤刪 4 個真錯字)、已棄用。
- 眉批改寫可能過度、失去學生語氣;無真值,上線後靠國語文老師回饋。
- 一篇 25~45 次呼叫:注意 Phase A 逾時預算與併發上限。
- 只驗過一個題目(115)。
