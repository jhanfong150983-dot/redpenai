## 判準架構：一套共用主判準，非純題本再加一層確認

**題本分兩種**：
- **純題本**：只有題幹＋選項，沒有作答位置/框。
- **非純題本**：本身要讓學生直接填寫（含作答框），原設計因應此。

**① 共用主判準（純＝非純都適用，判型骨幹）**：
`大題標題 ＞ 題幹指示用詞 ＞ 選項結構`
（標題如「選擇/是非/填空/簡答/注釋/造詞/應用」；題幹用詞如「圈出/打勾/解釋/計算/作圖」；選項結構如有無編號選項、幾個正解。）

**② 非純題本加成（僅有作答框時）**：
`印刷作答格式`（空括號／□／底線／工作區／「答：」答句／表格網格／地圖）。只在非純題本存在，當**確認訊號**、補題幹用詞不明時。**不是另一套規則，只是加一層佐證。**

## 已鎖定的判準規則（2026-09-07 user 拍板）

1. **單／多選、單／多勾**：題幹一定會寫或有選項可判；真判不出 → `single_choice` fallback。
2. **fill_blank vs fill_variants**：答案**單一固定值**＝`fill_blank`；**造詞／注釋／近義（容多元）**＝`fill_variants`。
3. **calculation vs word_problem**：看題幹有無「**故事或人物**」情境——有故事/人物＝`word_problem`；其餘（含「給邊長求面積」半情境）一律＝`calculation`。
4. **注釋／造詞／國字注音**：批改層一律 `fill_variants`（不新增題型），另掛「**子類標籤**」。**每子類各有作答框版型**：注釋 ✔／國字注音 ✔（現版型完美沿用）、**造詞＝沿用注釋版型**。
5. **圈選／選擇／勾選 純題本預設**（題幹未明講作答方式時）：有編號選項→`single_choice`；選項附 □→`single_check`；指示「圈」→`circle_select_one`。
6. **31 型維持不砍**：先全保留，罕見型待實測後再議增刪。

| 排序題 | `ordering` | 要求把數項標「**順序 1..N**」 | 格內/項目前填序號 | — |
| 圈詞題 | `mark_in_text` | 在一段**連續文章**中圈出特定詞（無預列選項） | 整段文章排版 | **圈文章詞** vs 圈選項 |

## 步驟 2：作答框版型（定案 v1 · 2026-09-07）

原型收斂成 3 種（現有生成器 `answerSheetGenerator.ts` 已有 numgrid/wide/bigbox），加「bigbox 可放底圖」一個新能力即涵蓋全部：

| 原型 | 對應題型 | 批改（步驟3預告）|
|---|---|---|
| `numgrid`（括號/□/○✗/序號/填空 變體）| single_choice·multi_choice·true_false·single_check·multi_check·ordering·fill_blank·multi_fill | code 精準 |
| 注釋框／國字注音雙格 | fill_variants 三子類（注釋✔·國字注音✔·造詞＝注釋版）| accessor 判準制 |
| `wide`／`bigbox` 書寫 | short_answer·calculation·word_problem | rubric／accessor |
| 組合框（符號格＋理由區）| compound_*_with_explain·multi_check_other·judge_with_correction | 複合鏈 |
| **`bigbox`＋底圖**（新能力）| circle_select·matching·mark_in_text·繪圖類(map_symbol/grid_geometry/connect_dots/diagram_draw/diagram_color)·map_fill·不規則表格 | **VJ 視覺判斷** |
| 結構表格格（規則矩陣）| table_check·規則 table_cell | code／群組 |

**拍板規則（2026-09-07）**：
- 「無法用基本框處理的一律用大框，讓老師編輯時加上底圖或圖片」。就地圈選/連線/圈詞/繪圖/表格→底圖解決。
- **細分**：規則矩陣（□表）盡量保「結構表格格」（code 批改最準）；只有不規則表/地圖/圖才 bigbox＋底圖。
- 底圖來源：MVP 老師手動加；未來可自動從題本裁該區域貼上。
- ⚠ 連動步驟 3：bigbox＋底圖的型批改會走 **VJ**（circle_select/matching/table 原本結構化→降級 VJ，較不精準較貴，步驟 3 要接對）。
- **待實作**：`AnswerSheetMakerStep` 加「這格放背景圖/圖片」＋生成器支援 box 帶 image。

## 步驟 3：批改鏈對接（盤點完成 · 2026-09-07）

Phase B 分流是旁路優先鏈：`manualBypass → VJ(diagram_color/map_symbol/grid_geometry) → levelRubric → map_fill → objective(確定性 CODE_FIRST+ordering+check/select) → cloze/glyph → rubric-judge(社會/自然+rubricsDimensions) → Accessor(通用預設)`。

**現況：31 型有 30 型已接對專屬批改路徑。** 三條路徑集合（已驗證）：
- `CODE_FIRST_CATEGORIES`（deterministic-compare.js:20）＝ single_choice, multi_choice, true_false, fill_blank, single_check, multi_check, multi_check_other, circle_select_one, ordering, multi_fill（10 型純 code）。
- `VISUAL_JUDGMENT_TYPES`（visual-judgment-grader.js:19）＝ **只有** diagram_color, map_symbol, grid_geometry（3 型）。
- 其餘走 Accessor（buildAccessorPrompt，staged-grading.js:7262）逐型規則；table_check 先正規化成 table_cell；map_fill 專屬 grader。

### 三個缺口／風險
1. **ordering**：Accessor 無專屬 bullet，靠確定性計分堵住；讀值含 `?`/不可讀 fail-open 回 Accessor → 通用計分分數亂跳。
2. **connect_dots / diagram_draw**：繪圖題卻不在 VJ 集合，只靠「read 轉文字→Accessor 判文字」，無視覺第二防線。
3. **table_check**：靠正規化成 table_cell 才有規則；漏正規化即掉通用 fallback（隱性接縫）。

### ⭐ VJ 的擷取側依賴（步驟 1 漏掉、最關鍵）
VJ 批改**不吃結構答案，吃 `vjRubric`**：Stage A0（`detectVisualRubric`，gemini.ts:5872）看老師畫的**正解 crop 自動生** vjRubric（老師不用手寫）。**目前 A0 只對 VJ 3 型跑**——要讓 connect_dots/diagram_draw 等走 VJ，必須：① 底圖上有老師正解 ② 擷取時對它們也跑 A0 生 vjRubric。機制已存在（作圖題就是這樣），要做的是**擴大 A0 觸發範圍**。

**vjRubric 結構**（db.ts:378，很小）：
```
{ itemLabels: string[], itemScores?: number[], condition?: string, gradingDefinition?: string }
```
範例（connect_dots）：
```json
{ "itemLabels": ["A-B 段","B-C 段","C-D 段","D-A 段"], "itemScores": [1,1,1,1],
  "condition": "把這一段兩端點連起來",
  "gradingDefinition": "兩正確端點相連＝對；連錯點或漏連＝錯。" }
```

### 分寸
畫圖類（connect_dots/diagram_draw）→ 走 VJ 很自然。circle_select/matching/mark_in_text 是「印刷內容上圈/連/畫記」→ vjRubric 勉強，**若選項位置抓得到就留結構化更準**。

### 步驟 3 待辦

- 批改路由改看「作答呈現形式」：加 `visualAnswer` 旗標（step 2 生成 bigbox+底圖時掛），有旗標即強制 VJ、不看底層 category。
- 補 ordering Accessor bullet、table_check 正規化防漏。

## 🕳 尚缺／待補（設計盤點後仍未覆蓋，2026-09-07）

1. **全部還是設計、零 code 落地**：三步都定案但沒改 code。一致性要等落地才實現（結構推斷仍走 7 型 SOLVE_TYPE_MENU）。
2. **題型可修正迴路（老師 override）**：題型是全鏈權威、AI 會錯，但 UI 目前「題型唯讀」（判分方式依題型決定、不開放切換）。**權威若不可修正，AI 判錯就全鏈錯**（框錯、批改鏈錯、試卷分析/家長報告錯）。需要老師能改題型且改動向下傳（框＋批改一起換）。之前「層級 2 下拉」就是這件事，被暫緩。
3. **子類偵測與儲存（注釋/造詞/國字注音）**：步驟 2 要靠子類選版型，但擷取時要判「這個 fill_variants 是哪個子類」並**存成欄位**。目前只有顯示層 `getDisplayTypeLabel` 推導，沒有儲存的判定訊號。
4. **純題本（無作答框）輸入是否真支援**：純/非純我們定義了判準，但 pipeline 有沒有真的支援「純題本」輸入待驗證——現在生成流程假設題本帶格式線索，真正無框的純題本結構推斷判不判得出題型未確認。
5. **防漂不變量**：questionCategory 要單一來源、下游不得重判。已知漂移接縫＝AnswerBank.tsx:518 fallback（extractAnswerKeyFromImages 25 型重判）＋ table_check 正規化漏接。落地要加守門/不變量。
6. **驗證／回放**：改題本分類 prompt 前要有「真實題本測試集」驗準確度（記憶鐵則：改 prompt 前先測原 AI ≥5 次），目前無 harness。
7. **落地順序**：步驟 1（題本輸出 31 型、退兩套字彙）是地基，步驟 2/3 都依賴它——落地要先做步驟 1。
